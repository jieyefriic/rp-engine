## 2. MCP Scenario A — 显式 MCP Tool Call (`mcp` 节点)

**Commit:** `bc61372`

### 实现

| 文件 | 改动 |
|------|------|
| `src/mcp/client.rs` | **新文件**。McpClient: Streamable HTTP JSON-RPC 2.0 客户端 |
| `src/mcp/mod.rs` | **新文件**。MCP 模块导出 |
| `src/nodes/mcp.rs` | **新文件**。McpExecutor: 从 mcp_servers 查找 server → 调用指定 tool → 写 state |
| `src/schema/workflow.rs` | 新增 `McpServerDef { url, auth }`, `McpAuth { auth_type, token }`, `PreparedWorkflow.mcp_servers` |
| `src/schema/node.rs` | `NodeType::Mcp` 变体, `NodeConfig` 新增 `server`, `tool` 字段 |
| `src/engine.rs` | `EngineError::McpError`, builder `.mcp_server()` / `.mcp_server_def()`, `ExecutionConfig.mcp_servers` merge 逻辑 |

### 关键发现

- **SSE 响应**: DeepWiki MCP server 返回 `text/event-stream`（SSE），不是 plain JSON。McpClient 需同时处理两种 Content-Type。
- **Session 管理**: 通过 `Mcp-Session-Id` header 维持会话。

### 验证

```
DEEPSEEK_API_KEY=... cargo run --example test_mcp_deepwiki
  → MCP client 连接 DeepWiki
  → tools/list 返回工具列表
  → read_wiki_structure 调用成功
  → SSE 响应正确解析
  → ✅ Scenario A PASSED
```

## 3. MCP Scenario B — LLM 驱动 MCP Tool Calling (`mcp_tools` + generate)

**Commit:** `bc61372`（同上）

### 实现

| 文件 | 改动 |
|------|------|
| `src/nodes/mcp_tools.rs` | **新文件**。McpToolsExecutor: 连接 MCP server → `tools/list` → 输出 tool 定义到 state |
| `src/schema/node.rs` | `NodeType::McpTools` 变体, `NodeConfig` 新增 `mcp_tool_sets: Vec<String>` |
| `src/nodes/generate.rs` | 从 mcp_tool_sets 引用的节点 state 读取 MCP tool 定义 → 注入 tool_defs → dispatch MCP tool calls |
| `src/nodes/mod.rs` | 注册 mcp / mcp_tools executor |

### 工作流程

```
mcp_tools 节点 → tools/list → tool 定义写入 state
                                    ↓
generate 节点 ← mcp_tool_sets 引用 ← 从 state 读取 tool 定义
  ↓
  inject MCP tools into tool_defs (alongside subgraph tools + skill tools)
  ↓
tool calling loop:
  LLM 返回 tool_call → dispatch:
    - load_skill/load_skill_reference → built-in skill 处理
    - MCP tool → route to MCP server
    - user tool → subgraph 执行
```

### 验证

```
DEEPSEEK_API_KEY=... cargo run --example test_mcp_tools_deepwiki
  → mcp_tools 节点发现 DeepWiki 工具
  → generate 节点注入 MCP tool 定义
  → DeepSeek LLM 自主调用 MCP tools
  → MCP tool call dispatch 到 DeepWiki server
  → ✅ Scenario B PASSED
```

### 已知限制

- **DeepSeek context window overflow**: 当 MCP tool 返回大量内容时（如完整 wiki 结构），可能超出 DeepSeek 的 context window 限制。这不是代码 bug，是模型限制。解决方案：使用更大 context window 的模型，或在 prompt 中限制返回范围。
